# Server deployment and automatic ORCID updates

This static website can be served by Apache, Nginx, GitHub Pages, or any other static hosting setup. The file `publications.html` is generated by:

```bash
python3 tools/generate_publications_from_orcid.py
```

The generator uses only the Python standard library and public ORCID records.

## Suggested server layout

Copy the website to:

```text
/var/www/computational_mechanics_soft_materials_group
```

Example:

```bash
sudo mkdir -p /var/www/computational_mechanics_soft_materials_group
sudo rsync -av ./ /var/www/computational_mechanics_soft_materials_group/
sudo chown -R www-data:www-data /var/www/computational_mechanics_soft_materials_group
```

Adjust the user/group if your web server uses a different account.

## Option A: daily update using cron

Edit the crontab:

```bash
crontab -e
```

Add:

```cron
0 6 * * * SITE_DIR=/var/www/computational_mechanics_soft_materials_group /var/www/computational_mechanics_soft_materials_group/deploy/update_publications_daily.sh
```

This regenerates `publications.html` every day at 06:00 server time. Logs are written to:

```text
/var/www/computational_mechanics_soft_materials_group/logs/orcid_publications_update.log
```

## Option B: daily update using systemd timer

Copy the service and timer files:

```bash
sudo cp deploy/cmsm-publications-update.service /etc/systemd/system/
sudo cp deploy/cmsm-publications-update.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now cmsm-publications-update.timer
```

Check status:

```bash
systemctl list-timers | grep cmsm
systemctl status cmsm-publications-update.timer
```

Run the update manually:

```bash
sudo systemctl start cmsm-publications-update.service
```

View logs:

```bash
tail -f /var/www/computational_mechanics_soft_materials_group/logs/orcid_publications_update.log
```

## Notes

- Cron uses the server's local timezone. On a Prague server, `0 6 * * *` means 06:00 Europe/Prague time.
- For production, `systemd` is usually more robust than cron because it has explicit status and missed-run handling through `Persistent=true`.
- If the website is deployed from Git, make sure the server-side generated `publications.html` is not immediately overwritten by a later deployment.
- If you use GitHub Pages instead of your own server, use the included GitHub Actions workflow instead of cron/systemd.
